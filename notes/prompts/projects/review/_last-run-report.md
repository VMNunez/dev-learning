# Pipeline self-report — review-audit

**Date:** 2026-07-14 · **Project:** projects/07-timetrack · **Scope:** backend (FORCE — gate was 8 days old)

- **Slices mapped** — 9: `auth`, `users`, `projects`, `time-entries`, `reports` (flow + security each), plus `persistence-config` and `security-infra`. The map was right; `reports` (Step 6) had never been reviewed and returned the highest-value correctness finding, which vindicates deriving the resource list from the controllers rather than from the last run's backlog.
- **Report discipline** — clean. All 9 returned bounded tables + traces; none had to be truncated. The `users` security reviewer proactively flagged its High as a likely cross-slice duplicate and told the orchestrator to expect it — that made the merge easier and is worth keeping in the prompt.
- **Trace verification** — all 9 traces covered every file/endpoint their slice owned. No re-dispatch. **One false alarm:** the `auth` flow reviewer reported a hardcoded JWT secret as High; `application.properties:10` is `app.jwt.secret=${JWT_SECRET}`. `security-infra` had it right. The orchestrator caught it only because two slices contradicted each other — a single-slice review would have shipped it. Cheap mitigation: the flow prompt should require quoting the offending line for any config finding.
- **Dedup** — 9 cross-slice duplicates merged. The inactive-user rule (`.disabled(!user.isActive())`) surfaced independently in **5** slices; `User.active`/`Project.active` defaults, `@GeneratedValue`, `@Transactional`, N+1, hours precision, `GROUP BY name`, missing `@PreAuthorize` on entries, and the unlogged catch-all each surfaced in 2–3. Matching them was easy — same file:line — so the business-rule-tag idea is still unproven as necessary.
- **Scope limit did real work** — Step 8 (tests) is unbuilt, so every reviewer was told upfront to write "out of scope" instead of reporting missing tests. All 9 complied. Without that instruction the run would have produced ~9 spurious High "no tests" findings. **This belongs in the orchestrator prompt itself**, not in per-run instructions: Step 0 should read §0, work out which steps are unbuilt, and pass the exclusion into every dispatch.
- **Verdict** — change worth considering: two small prompt edits, both evidenced above — (1) flow prompt must quote the source line for config findings (the false JWT-secret High), and (2) review-audit Step 0 must derive the unbuilt-step exclusion and pass it to every subagent, rather than relying on the operator to add it by hand.
