# Closed recommendations — the resolved half of `_recommendation-ledger.md`

**What this file is.** One line per resolved `REC-NNN`, ordered by ID, in the closure schema step 4 of
the ledger states: the ID, what the item was, `cold reviewer: approve | approve-with-tightening`, the
two-map declaration, and the implementation commit. Nothing else. Beyond those fields a **rejected**
item keeps its reason, because that reason is the only thing stopping the next analysis re-raising it,
and a **residue** clause names work the item left open. The reviewer field starts at `REC-107` and the
two-map field at the first item collapsed after 2026-08-07; earlier lines are not retrofitted. On disk that
second field becomes continuous at `REC-058`, and that is the number `validate-prompt-system.ps1`
invariant 9 enforces — it reads every line here against this schema and fails the run on a missing
field, a broken ID order, a `{commit}` template, or an ID that is open in the ledger and closed here
at once. The one-line budget it only **reports**, as a character count beside the longest row.

**Where the reasoning is.** In `git log -p` on this file and on the ledger — the closing commit removes
the row from `## Open` there and adds the line here, so either side reaches it. Restating an argument
here buys nothing and costs the only thing this file is read for, which is a scan for one ID. If a line
needs a paragraph, the rule it established belongs in `_recommendation-resolution-doctrine.md` instead,
and step 4's budget — one line plus at most one promotion — is what that rule is.

**Why it is a separate file.** Split out 2026-08-18, the day the case law was. The ledger is read to
answer *what is open and what happens next*, and 156 resolved lines sitting under that queue is the
same defect the doctrine split fixed from the other end: the working half of the file was the part
nobody could find. Do not split this one further — an archive cut by era stops being a single
deduplication source, which is the one job it has.

**Who writes it.** Whoever resolves a ledger row, in the same commit as the row's removal from `## Open`.
Never a prompt run, never a skill, never a build step.

**Who reads it.** `/system-gaps`, deduplicating a candidate against resolved work — including against
**rejected** rows, whose reason discharges the candidate — and any session checking whether a problem
has been ruled on before. It is the ledger's own preamble that scopes what may be a row at all; this
file only records the ones that were.
