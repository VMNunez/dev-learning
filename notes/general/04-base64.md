# Base64

Docs: [MDN — Base64](https://developer.mozilla.org/en-US/docs/Glossary/Base64) · [jwt.io](https://jwt.io) (paste any JWT to decode it)

---

Base64 is an encoding — it converts binary data (bytes) into a text-safe string using only 64 characters: A–Z, a–z, 0–9, `+`, `/`.

```
Binary:  11001010 10110101 ...
Base64:  "yrd8..."
```

**Base64 is not encryption.** It is easily reversible. If you encode `"hello"` to Base64, anyone can decode it back to `"hello"` in one step. It is used for **transport safety**, not for security.

> The point of Base64 is not to hide data — it is to represent binary data in a format that can travel safely through systems that only handle text (HTTP headers, JSON, config files).

## Where Base64 appears in TimeTrack

### JWT secret in application.properties

```properties
app.jwt.secret=dGhpcyBpcyBhIHNlY3JldCBrZXkgZm9yIEpXVA==
```

The signing key is a binary value. To store it in a text config file, it is Base64-encoded. In `JwtUtil`, it is decoded back to bytes before use:

```java
byte[] keyBytes = Decoders.BASE64.decode(secret);
return Keys.hmacShaKeyFor(keyBytes);
```

### JWT token structure

A JWT has three parts separated by dots:

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ2aWN0b3JAZ...  .SflKxwRJSMeKKF2...
        ↑                        ↑                          ↑
    header (Base64)         payload (Base64)         signature (HMAC hash)
```

The header and payload are just Base64-encoded JSON — paste any JWT into [jwt.io](https://jwt.io) and you can read them directly. Only the signature is a cryptographic value that proves the token was not modified.

This is why the JWT secret must never be committed to git: anyone with the secret can forge valid tokens with any `sub` (user email) they want.
