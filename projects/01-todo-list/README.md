# To-do List

My 1st learning project — task manager where users add, complete and delete tasks with live filtering.

---

## Why this project

Every Angular app is built from components, services and reactive state. I built this project to understand how those building blocks work from scratch — how components communicate, how signals keep the UI in sync, and how services share state across the app.

## Features

- Add a task by typing a title and pressing Enter
- Mark a task as complete or bring it back to pending
- Delete a task from the list
- Filter tasks by status: All, Active, Completed
- Live counter showing how many tasks are still pending out of the total
- Message shown when no task matches the selected filter

---

## Architecture decisions

- Service-owned state to keep task logic out of the components and reachable from anywhere in the app
- `signal()` and `computed()` for state to get reactivity without subscriptions to manage or clean up
- `input()` and `output()` for parent-child communication to keep the repeated leaf component dumb — data down, events up
- `computed()` for the filtered list and the counters to recalculate them automatically whenever the task list changes
- A local `signal<Filter>` in the list component to keep the view filter out of the service — it is UI state, not task data
- Ids generated by a private counter in the service to avoid the duplicate ids `Date.now()` produces within one millisecond
- Router with a single `''` route to boot the app through `provideRouter` from day one instead of retrofitting routing later

---

## Tradeoffs

- Signals over RxJS `BehaviorSubject` — no subscription lifecycle to manage, so the first project spends its budget on components rather than streams
- State in a service over state in the page component — it survives the component and a second page can inject it without passing it through inputs
- `completed: boolean` over a `status` union — two states with no transition rules between them, so a union would add a type without adding a guarantee
- In-memory array over `localStorage` — persistence is what project 04 teaches; adding it here would hide the signal behind a second problem

## What I learned

- `@Component` — how to create a standalone component
- `input()` and `output()` — signal-based communication between components
- `@for` and `@empty` — render a list and handle the empty state
- `@if` — show or hide elements based on a condition
- `@Injectable` with `providedIn: 'root'` — one shared instance created on first use
- `inject()` — function-based dependency injection, no constructor parameter
- `signal()`, `signal.set()`, `signal.update()` — reactive state and its two write APIs
- `computed()` — derived values that recalculate when their signals change
- `[class.x]` — apply a CSS class conditionally from state
- `(keyup.enter)` — key event modifier; handles Enter without inspecting the event object
- `type` union — `type Filter = 'all' | 'active' | 'completed'` makes an invalid filter a compile error, not a silent no-match
- Exhaustive `switch` over a union type — omitting `default` makes a new union member a compile error
- `styleUrl` — a component declares one only when it has styles; an empty stylesheet is a build dependency that buys nothing
- `componentRef.setInput()` — a required input has no parent in a test, so the harness must supply it before the first render
- Service-owned state — one writer, many readers; data down through `input()`, events up through `output()`
- State justified by its readers — a signal no template reads is not state, so the root component of a routed app declares none
- CSS custom properties — `:root` and `var()` for a single source of colours
- Flexbox — `display: flex`, `justify-content`, `align-items`, `gap`
- `justify-content` / `align-items` — alignment belongs to the flex container; on a non-flex element they are parsed and silently ignored

## Project structure

```
src/app/
├── app.ts                        ← root component, renders <router-outlet />
├── app.routes.ts                 ← one route: '' → TodoPage
├── app.config.ts                 ← application providers (provideRouter)
└── pages/
    └── todo-page/
        ├── todo-page.ts          ← page shell: composes form + list, holds no state
        ├── models/               ← the Task interface
        ├── services/             ← TaskService: owns the signal and the add/toggle/delete methods
        └── components/
            ├── task-form/        ← input box, calls addTask on the service
            ├── task-list/        ← reads the signal, derives counters and the filtered list
            └── task-item/        ← presentational row: input() task, output() toggle and delete
```
