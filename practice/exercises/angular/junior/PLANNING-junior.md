This is the persistent practice route. The shared contract lives in
`notes/prompts/practice/exercises/_internal/_practice-standard.md`, whose §H `angular — junior` section
sets the environment: one Angular workspace in this folder, one application per batch, one folder per
exercise under that batch's `src/app/`. `practice-session` plans, generates and grades this route.
Coverage defines scope; the notes plan defines grouping and prerequisites. Every task below reserves its
purpose, concepts, folder and pass condition before a session writes its statement. No exercise source
file is generated by this plan.

## How to use this plan

Ask to practise Angular junior, a block or a concept. While the `## Essential route` below is not
passed it is the default order for an Angular request that names no block or concept; table order,
subject to block prerequisites and `After`, applies after it and to a named block. `File` is the
exercise folder's name inside the batch's `src/app/` (`exNNN-slug`, `NNN` being the plan ID's number);
its demo route, when it has one, is `/exNNN`. First tasks introduce one concept; transfer tasks change
the problem; integration tasks combine two or three already attempted concepts. Every `variant` occurs
in a later batch than its first attempt.

**Evidence follows §H, and each pass condition names which kind it takes.**

- *The given spec passes* — a logic exercise ships a spec written at generation that tests behaviour
  through the public API and the rendered DOM; he runs `ng test lote-NN --include app/exNNN-slug
  --watch=false` and pastes what it printed under `// My output:`. A given spec he edited is not
  evidence. A spec that uses a router runs it through `RouterTestingHarness`; one that times work uses
  fake timers.
- *Manual check (`Observed`)* — an interface exercise states an action and its expected result, and he
  writes what the browser did under `<!-- Observed: … -->`. Output that depends on the time zone, on
  layout or on the browser's own history — what its Back button does — is always checked this way,
  never by a given spec; the application's own record of navigations is logic and has a given spec.
- *Graded by reading* — a change with no observable effect at run time (a rename, an injection style,
  a narrower type) carries no given spec, since one would pass before he answers; `ng build` passes and
  the grader reads the code.
- *`Observed` quoting the build* — a delivery exercise (blocks 19 and 23) has him run
  `ng build lote-NN` and quote the lines the statement names.
- *Your spec passes* — **blocks 24 and 25 are the first in which he writes specs.** Before them every
  spec is given; from them on the spec is an answer file whose skeleton holds one `it.todo(…)`, and its
  pass condition says what it must assert. In those blocks a supplied spec — a Jasmine suite, a
  failing setup, a legacy module — is shipped as `.txt` or quoted in a comment, never as a runnable
  spec. Where a row asks his spec to fail against a broken version, the folder ships `broken-*.ts`
  beside the unit, the statement names the one import line of his spec he switches to it, and he
  pastes both runs under `// My output:`. An integration that combines a feature with its test exists
  only from those blocks on.

**What generation keeps green, and what it keeps red.** The generation check builds and tests every
batch untouched, so anything that would break the build or the test run — a missing import, a
`private` member read by the template, a call outside an injection context — is delivered **commented
out**; enabling it, recording the error and fixing it is the task. The same check refuses a given spec
that passes before he answers, so a refactor or migration task quotes the code before the change in a
comment or a `.txt` file and his answer files start as skeletons that compile and on which the given
spec fails only on its assertions ("red on the skeleton"). Configuration
an exercise owns (an `ApplicationConfig`, providers, a router feature such as `withRouterConfig`,
`withHashLocation` or a `TitleStrategy`) is exported from its folder and applied by its given spec or
spread into the batch's router at generation; a batch carries at most one exercise that configures the
batch's router. HTTP reads a JSON file the batch ships under `public/`; what a static file cannot answer
— a POST, a status code, a delay — runs through a given spec with `HttpTestingController`.
No answer touches a root file and no exercise adds a dependency; configuration that differs between
environments is a file the batch ships under `public/`, never a `fileReplacements` entry.

No batch is generated from this route until the `angular — junior` section of the standard's §H
carries its `Pilot folded:` line naming `01-book-catalog` (§C).

Statements are in English; his comments and explanations are in Spanish.
