This is the persistent practice route. The shared contract lives in
`notes/prompts/practice/exercises/_internal/_practice-standard.md`, whose §H `spring-boot — junior`
section sets the environment: one Maven project in this folder, one module per batch, one package per
exercise, H2 in memory. `practice-session` plans, generates and grades this route. Coverage defines
scope; the notes plan defines grouping and prerequisites. Every task below reserves its purpose,
concepts, package name and pass condition before a session writes its statement. No exercise source file
is generated by this plan.

## How to use this plan

Ask to practise Spring Boot junior, a block or a concept. While the `## Essential route` below is not
passed it is the default order for a Spring Boot request that names no block or concept; table order,
subject to block prerequisites and `After`, applies after it and to a named block. `File` is the
exercise's package name inside the batch module, `practice.loteNN.{File}` (`exNNN_slug`, `NNN` being the
plan ID's number), under `src/main/java` and mirrored under `src/test/java`; its own resources are
`{File}.properties`, `{File}-{profile}.properties` and the `{File}/` folder. First tasks introduce one
concept; transfer tasks change the problem; integration tasks combine two or three already attempted
concepts. Every `variant` occurs in a later batch than its first attempt.

**Evidence follows §H, and each pass condition names which kind it takes.**

- *The given test passes* — the exercise ships a test written at generation that calls only the public
  surface the statement fixes: `@WebMvcTest` with `MockMvc` for a controller, `@DataJpaTest` (with
  `TestEntityManager`) for a mapping or a repository, plain JUnit with Mockito for a service,
  `@RestClientTest` for an outbound call, `@SpringBootTest` where the task is wiring or configuration.
  He runs `.\mvnw -pl NN-slug test "-Dtest=practice.loteNN.{File}.**"` and pastes the `Tests run:` line
  and any failure under `// My output:`. A given test he edited is not evidence. Where a pass condition
  counts statements, the given test turns on Hibernate's statistics in the exercise's properties.
- *A started context fails* — a task about startup ("the failure the statement declares") ships given
  code that does not start; its given test starts the context and asserts on what the exercise serves,
  so on the untouched batch it fails with exactly the declared cause, and it passes once his fix lets
  the context start.
- *`Observed`* — what only a started application or its log shows (a warning, the condition report,
  the SQL Hibernate sends): the statement names the action and what should be seen, and he writes what
  he saw under `// Observed:`.
- *Graded by reading* — a change with no behaviour of its own (a removed literal, a moved prefix, the
  other token form) is read by the grader beside a given test that pins the behaviour; the code to
  change is quoted in a comment and the skeleton holds its class with neutral bodies, as in block 14, so
  the pin is red until he rewrites it.
- *His test passes* — **block 09 is the first in which he writes tests.** Before it every test is given;
  in it the test is an answer file whose skeleton holds one `@Disabled("pending — your answer")` method,
  and its pass condition says what it must assert. Where a row asks his test to fail against a broken
  version, the package ships `Broken*` beside the subject, the statement names the one line of his test
  he switches to it, and he pastes both runs under `// My output:`. A test-writing integration exists
  only from that block on.

**What generation keeps green, and what it keeps red.** The generation check runs `.\mvnw -pl NN-slug
test` on every batch untouched, so the module must compile before he writes a line: the statement fixes
every class name, signature, endpoint and DTO field a given test calls, and the skeleton declares them
with neutral bodies. A given test that needs a bean only his answer registers looks it up —
`getBeanProvider(...).getIfAvailable()`, or an `ApplicationContextRunner` — rather than injecting it, so
the untouched context starts and the test fails on its assertion. A port of maintained code (block 14) quotes the old code in a comment, never as
compilable source. Each exercise is an application of its own (`ExNNNApplication`), so no exercise sees
another's beans, entities or configuration, and nothing sits where Boot looks in every context of the
module. Where the module declares Spring Security, every exercise that does not practise security runs
its given test with the filters off, and the skeleton of a test he writes in such an exercise carries
the `@AutoConfigureMockMvc(addFilters = false)` line, supplied. No answer edits a `pom.xml` and no exercise adds a dependency.

Statements are in English; his comments and explanations are in Spanish.
